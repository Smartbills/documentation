description: "Delete a location from your account"
---

## Overview

Permanently delete a business location from your Smartbills account. This action cannot be undone.

<Warning>
  **Destructive Action**: Deleting a location is permanent and cannot be undone. Consider the impact on related receipts and transactions.
</Warning>

## Authentication

<ParamField header="Authorization" type="string" required>
  Bearer token for authentication. Format: `Bearer YOUR_API_KEY`
</ParamField>

## Required Scopes

- `locations.write`

## Path Parameters

<ParamField path="id" type="integer" required>
  The unique identifier of the location to delete
</ParamField>

## Response

Returns the deleted location object for confirmation.

<RequestExample>

```bash cURL
curl --request DELETE \
  --url https://api.smartbills.io/v1/locations/12345 \
  --header 'Authorization: Bearer YOUR_API_KEY'
```

```javascript JavaScript
import { SBClient } from "@smartbills/sdk";

const client = new SBClient({ apiKey: 'YOUR_API_KEY' });

const deletedLocation = await client.locations.delete(12345);
console.log('Deleted location:', deletedLocation);
```

```python Python
from smartbills import SmartBills

client = SmartBills(api_key='YOUR_API_KEY')

deleted_location = client.locations.delete(12345)
print('Deleted location:', deleted_location)
```

```csharp C#
using Smartbills.NET;

var client = new SBClient("YOUR_API_KEY");

var deletedLocation = await client.Locations.DeleteAsync(12345);
Console.WriteLine($"Deleted location: {deletedLocation.Name}");
```

</RequestExample>

## Error Responses

| Status Code | Error Code | Description |
|------------|------------|-------------|
| 401 | UNAUTHORIZED | Missing or invalid API key |
| 403 | FORBIDDEN | Insufficient permissions |
| 404 | NOT_FOUND | Location not found |
| 409 | CONFLICT | Cannot delete location with active receipts |
| 429 | RATE_LIMIT_EXCEEDED | Too many requests |

## Important Considerations

<AccordionGroup>
  <Accordion title="Impact on Receipts" icon="receipt">
    Check for associated receipts before deleting a location.
    
    ```javascript
    const receipts = await client.receipts.list({ locationId: 12345 });
    
    if (receipts.data.length > 0) {
      console.warn(`Location has ${receipts.data.length} receipts`);
      // Handle receipts before deletion
    } else {
      await client.locations.delete(12345);
    }
    ```
  </Accordion>

  <Accordion title="Soft Delete Alternative" icon="archive">
    Consider marking locations as inactive instead of deleting:
    
    ```javascript
    await client.locations.update(12345, {
      ...currentLocation,
      isActive: false
    });
    ```
  </Accordion>

  <Accordion title="Confirmation Pattern" icon="triangle-exclamation">
    Always implement user confirmation before deletion.
  </Accordion>
</AccordionGroup>
