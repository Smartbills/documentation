## Overview

Create a new expense report to organize and submit expenses for approval. You can create an empty report and add expenses later, or include expense IDs during creation.

## Authentication

<ParamField header="Authorization" type="string" required>
  Bearer token for authentication. Format: `Bearer YOUR_API_KEY`
</ParamField>

## Request Body

<ParamField body="name" type="string" required>
  Descriptive name for the expense report
  
  Example: "January 2024 Travel Expenses"
</ParamField>

<ParamField body="businessId" type="integer" required>
  ID of the business this report belongs to
</ParamField>

<ParamField body="description" type="string">
  Detailed description of the report purpose
  
  Example: "Business trip to NYC for client meetings"
</ParamField>

<ParamField body="startDate" type="string">
  Start date of the expense period (ISO 8601 format: YYYY-MM-DD)
  
  Example: "2024-01-01"
</ParamField>

<ParamField body="endDate" type="string">
  End date of the expense period (ISO 8601 format: YYYY-MM-DD)
  
  Example: "2024-01-31"
</ParamField>

<ParamField body="expenseIds" type="array">
  Array of expense IDs to include in the report
  
  Example: `[12345, 12346, 12347]`
</ParamField>

<ParamField body="projectId" type="integer">
  ID of the project this report is associated with
</ParamField>

<ParamField body="departmentId" type="integer">
  ID of the department submitting the report
</ParamField>

<ParamField body="tags" type="array">
  Array of tags for categorization
  
  Example: `["Q1-2024", "client-visit", "NYC"]`
</ParamField>

<ParamField body="notes" type="string">
  Additional notes for the approver
</ParamField>

<ParamField body="metadata" type="object">
  Custom metadata key-value pairs
  
  Example: `{"costCenter": "CC-001", "purchaseOrder": "PO-12345"}`
</ParamField>

## Validation Rules

### Report Name
- **Required**: Yes
- **Min length**: 3 characters
- **Max length**: 200 characters
- **Format**: Any text

### Business ID
- **Required**: Yes
- **Must exist**: Business must be accessible by the user
- **Type**: Integer

### Date Range
- **Required**: No (both optional)
- **Format**: YYYY-MM-DD
- **Validation**: `endDate` must be after `startDate` if both provided

### Expense IDs
- **Required**: No (can create empty report)
- **Validation**: 
  - All expenses must exist
  - All expenses must belong to the specified business
  - All expenses must be in "pending" status
  - Expenses cannot already be in another report

| Status Code | Error Code | Description |
|------------|------------|-------------|
| 400 | VALIDATION_FAILED | Invalid request data |
| 400 | INVALID_DATE_RANGE | End date before start date |
| 400 | EXPENSE_NOT_FOUND | One or more expense IDs don't exist |
| 400 | EXPENSE_ALREADY_IN_REPORT | Expense already in another report |
| 401 | UNAUTHORIZED | Missing or invalid API key |
| 403 | FORBIDDEN | No access to specified business |
| 404 | BUSINESS_NOT_FOUND | Business ID doesn't exist |
| 429 | RATE_LIMIT_EXCEEDED | Too many requests |

## Use Cases

### Create Empty Report

Create a report and add expenses later:

```javascript
const report = await fetch('https://api.smartbills.io/v1/expense-reports', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer YOUR_API_KEY',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: 'February 2024 Expenses',
    businessId: 100,
    description: 'Monthly expense report'
  })
}).then(r => r.json());

// Add expenses later using PATCH /v1/expense-reports/{reportId}
```

### Create with Expenses

Create a report with expenses in one request:

```javascript
const report = await fetch('https://api.smartbills.io/v1/expense-reports', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer YOUR_API_KEY',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: 'January 2024 Travel',
    businessId: 100,
    expenseIds: [12345, 12346, 12347],
    startDate: '2024-01-01',
    endDate: '2024-01-31'
  })
}).then(r => r.json());
```

### Create with Metadata

Include custom metadata for integration:

```javascript
const report = await fetch('https://api.smartbills.io/v1/expense-reports', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer YOUR_API_KEY',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: 'Project Alpha Expenses',
    businessId: 100,
    projectId: 42,
    metadata: {
      costCenter: 'CC-001',
      purchaseOrder: 'PO-12345',
      clientId: 'CLIENT-789',
      billingCode: 'BILL-456'
    }
  })
}).then(r => r.json());
```

## Best Practices

<AccordionGroup>
  <Accordion title="Descriptive Names" icon="tag">
    Use clear, descriptive names that indicate:
    - Time period (month, quarter, trip dates)
    - Purpose (travel, office supplies, client meeting)
    - Project or client name
    
    **Good examples:**
    - "January 2024 Office Supplies"
    - "Q1 2024 Marketing Expenses"
    - "NYC Client Visit - Jan 15-18"
    
    **Avoid:**
    - "Report 1"
    - "Expenses"
    - "Misc"
  </Accordion>

  <Accordion title="Set Date Ranges" icon="calendar">
    Always include start and end dates when possible:
    - Helps filter eligible expenses
    - Provides context for approvers
    - Useful for reporting and analytics
    - Required by some company policies
  </Accordion>

  <Accordion title="Add Context" icon="note-sticky">
    Include a description that explains:
    - Purpose of the expenses
    - Project or client details
    - Any special circumstances
    - Relevant background information
    
    This helps approvers make informed decisions.
  </Accordion>

  <Accordion title="Use Tags" icon="tags">
    Tag reports for better organization:
    - Project names
    - Client names
    - Department codes
    - Fiscal periods
    - Billable/non-billable
    
    Tags make reports easier to find and analyze later.
  </Accordion>

  <Accordion title="Validate Expenses" icon="check">
    Before creating a report:
    - Verify all expenses are categorized
    - Ensure receipts are attached
    - Check amounts are correct
    - Confirm dates are accurate
    
    This prevents errors and speeds up approval.
  </Accordion>
</AccordionGroup>

## Next Steps

After creating a report:

1. **Add More Expenses** (if needed)
   ```
   PATCH /v1/expense-reports/{reportId}
   ```

2. **Review Report Details**
   ```
   GET /v1/expense-reports/{reportId}
   ```

3. **Submit for Approval**
   ```
   POST /v1/expense-reports/{reportId}/submit
   ```
