## Overview

To ensure fair usage and maintain optimal performance, the Smartbills API implements rate limiting. This helps control incoming request traffic and provides a smooth, predictable API experience for all users.

<Note>
  **Fair usage**: Rate limits ensure that no single user can monopolize API resources, maintaining quality service for everyone.
</Note>

## Rate Limits by Plan

| Plan | Requests Per Minute | Burst Capacity | Daily Limit |
|------|---------------------|----------------|-------------|
| **Free** | 60 | 60 | 5,000 |
| **Professional** | 300 | 300 | 50,000 |
| **Business** | 1,000 | 1,000 | 200,000 |
| **Enterprise** | Custom | Custom | Custom |

<Tip>
  **Need higher limits?** Enterprise customers can request custom rate limits. Contact [sales@smartbills.io](mailto:sales@smartbills.io) for details.
</Tip>

## Rate Limit Headers

Every API response includes rate limit information in the headers:

```http
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 1704067200
```

<ResponseField name="X-RateLimit-Limit" type="integer">
  Maximum number of requests allowed per minute for your plan
</ResponseField>

<ResponseField name="X-RateLimit-Remaining" type="integer">
  Number of requests remaining in the current window
</ResponseField>

<ResponseField name="X-RateLimit-Reset" type="integer">
  Unix timestamp (in seconds) when the rate limit window resets
</ResponseField>

## Rate Limit Exceeded Response

When you exceed the rate limit, you receive a `429 Too Many Requests` response:

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
Retry-After: 60
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1704067200
```

```json
{
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Rate limit exceeded. Please try again later.",
    "retryAfter": 60
  }
}
```

The `Retry-After` header indicates how many seconds to wait before retrying.

## Handling Rate Limits

### Check Rate Limit Headers

Always monitor rate limit headers in your application:

<CodeGroup>

```bash cURL
curl --request GET \
  --url https://api.smartbills.io/v1/expenses \
  --header 'Authorization: Bearer YOUR_API_KEY' \
  --header 'x-tenant-id: 123' \
  --verbose 2>&1 | grep -i "x-ratelimit"
```

```javascript JavaScript
import { SmartbillsClient } from '@smartbills/sdk';

const client = new SmartbillsClient({
  accessToken: 'YOUR_API_KEY',
  businessId: 123
});

// When making raw fetch requests, check headers:
const response = await fetch('https://api.smartbills.io/v1/expenses', {
  headers: {
    'Authorization': 'Bearer YOUR_API_KEY',
    'x-tenant-id': '123'
  }
});

const limit = response.headers.get('X-RateLimit-Limit');
const remaining = response.headers.get('X-RateLimit-Remaining');
const reset = response.headers.get('X-RateLimit-Reset');

console.log(`Rate limit: ${remaining}/${limit}`);
console.log(`Resets at: ${new Date(reset * 1000)}`);

if (remaining < limit * 0.1) {
  console.warn('Approaching rate limit!');
}
```

```python Python
from smartbills import SmartbillsClient
import requests
from datetime import datetime

# When making raw requests, check headers:
response = requests.get(
    'https://api.smartbills.io/v1/expenses',
    headers={
        'Authorization': 'Bearer YOUR_API_KEY',
        'x-tenant-id': '123'
    }
)

limit = int(response.headers.get('X-RateLimit-Limit', 0))
remaining = int(response.headers.get('X-RateLimit-Remaining', 0))
reset = int(response.headers.get('X-RateLimit-Reset', 0))

print(f"Rate limit: {remaining}/{limit}")
print(f"Resets at: {datetime.fromtimestamp(reset)}")

if remaining < limit * 0.1:
    print("Warning: Approaching rate limit!")
```

</CodeGroup>

### Implement Exponential Backoff

When you receive a 429 error, implement exponential backoff:

<CodeGroup>

```javascript JavaScript
async function makeRequestWithRetry(client, fn, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      if (error.status === 429) {
        const retryAfter = error.retryAfter || Math.pow(2, attempt);
        const waitTime = retryAfter * 1000;

        console.log(`Rate limited. Waiting ${retryAfter}s before retry...`);
        await new Promise(resolve => setTimeout(resolve, waitTime));
        continue;
      }

      throw error;
    }
  }

  throw new Error('Max retries exceeded');
}

// Usage
const expense = await makeRequestWithRetry(client, () =>
  client.expenses.get(12345)
);
```

```python Python
import time
from smartbills.errors import SmartbillsRateLimitError

def make_request_with_retry(fn, max_retries=3):
    for attempt in range(max_retries):
        try:
            return fn()
        except SmartbillsRateLimitError as e:
            retry_after = e.retry_after or (2 ** attempt)

            print(f"Rate limited. Waiting {retry_after}s before retry...")
            time.sleep(retry_after)
            continue

    raise Exception("Max retries exceeded")

# Usage
expense = make_request_with_retry(lambda: client.expenses.get(12345))
```

</CodeGroup>

## Best Practices

<AccordionGroup>
  <Accordion title="Use Caching" icon="database">
    Cache API responses to reduce redundant requests. Use time-based cache invalidation for data that does not change frequently.
  </Accordion>

  <Accordion title="Use Pagination Efficiently" icon="list">
    Use the maximum page size (100) for batch processing to minimize the number of API calls. See [Pagination](/api-reference/pagination) for details.
  </Accordion>

  <Accordion title="Batch Requests" icon="layer-group">
    Combine multiple operations into single requests when batch endpoints are available (e.g., batch update expenses).
  </Accordion>

  <Accordion title="Use Webhooks Instead of Polling" icon="webhook">
    Use webhooks to receive real-time event notifications instead of polling the API for changes. See [Webhooks](/api-reference/webhooks) for setup instructions.
  </Accordion>

  <Accordion title="Implement Request Queuing" icon="list-ol">
    Queue requests and process them at a controlled rate to avoid bursts that exceed your rate limit.
  </Accordion>

  <Accordion title="Monitor Usage" icon="chart-line">
    Track your API usage patterns and set up alerts when approaching rate limits. Review usage regularly and optimize high-frequency calls.
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Consistently hitting rate limits" icon="gauge-high">
    1. Optimize your code to reduce unnecessary requests
    2. Implement caching for frequently accessed data
    3. Use webhooks to replace polling patterns
    4. Batch operations when possible
    5. Consider upgrading your plan
  </Accordion>

  <Accordion title="Rate limit headers missing" icon="question">
    Ensure you are using the latest API version (v1) and check that your HTTP client is not stripping response headers.
  </Accordion>

  <Accordion title="Unexpected 429 errors" icon="triangle-exclamation">
    Check for multiple instances of your application running, shared API keys across services, or automated scripts using the same key. Use separate API keys for each environment and service.
  </Accordion>
</AccordionGroup>

<Warning>
  **Important**: Rate limits are per API key. Using the same key across multiple services will share the rate limit.
</Warning>
