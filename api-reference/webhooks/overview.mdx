## What are Webhooks?

Webhooks allow your application to receive real-time notifications when events occur in Smartbills. Instead of polling the API, webhooks push data to your specified endpoint.

## How Webhooks Work

<Steps>
  <Step title="Configure">
    Register a webhook URL in Smartbills
  </Step>
  <Step title="Event Occurs">
    An event happens (expense created, report approved, etc.)
  </Step>
  <Step title="Notification Sent">
    Smartbills sends an HTTP POST to your URL
  </Step>
  <Step title="Process">
    Your server processes the webhook payload
  </Step>
</Steps>

## Webhook Payload

All webhooks follow this structure:

```json
{
  "id": "evt_abc123",
  "type": "expense.created",
  "created": "2025-01-15T10:30:00Z",
  "data": {
    "object": {
      "id": 12345,
      "merchant": "Office Depot",
      "amount": 45.99
    }
  }
}
```

## Security

### Signature Verification

All webhooks include a signature header for verification:

```
X-Smartbills-Signature: sha256=abc123...
```

Verify the signature using your webhook secret:

```javascript
const crypto = require('crypto');

function verifyWebhook(payload, signature, secret) {
  const expected = crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('hex');
  return `sha256=${expected}` === signature;
}
```

### IP Allowlist

Webhook requests come from these IPs:

- 52.0.0.0/8 (production)
- 34.0.0.0/8 (production)

## Retry Policy

If your endpoint returns an error, Smartbills retries:

| Attempt | Delay |
|---------|-------|
| 1 | Immediate |
| 2 | 5 minutes |
| 3 | 30 minutes |
| 4 | 2 hours |
| 5 | 24 hours |

After 5 failures, the webhook is disabled.

## Best Practices

<Tip>
**Respond quickly** - Return 200 within 30 seconds.
</Tip>

<Tip>
**Process async** - Queue events for background processing.
</Tip>

<Tip>
**Handle duplicates** - Events may be sent more than once.
</Tip>

<Tip>
**Verify signatures** - Always validate webhook authenticity.
</Tip>
