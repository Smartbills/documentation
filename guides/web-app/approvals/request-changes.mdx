## Overview

When a report has issues that the submitter can fix, requesting changes is the best approach. Unlike rejection, this action keeps the report intact and lets the employee make corrections and resubmit without creating a new report from scratch.

<Tip>
  **More collaborative than rejecting.** Request Changes is the recommended action when the report is mostly correct but needs minor fixes. The submitter can modify expenses, attach missing receipts, and resubmit the same report.
</Tip>

## Steps

<Steps>
  <Step title="Open the Pending Report">
    Navigate to **Approvals** in the left sidebar and click on the report you want to review. Only reports with a **Pending** status can have changes requested.

    <Frame>
      <img src="/images/guides/web-app/approvals/open-report-for-changes.png" alt="Opening a pending report from the approval queue" />
    </Frame>
  </Step>

  <Step title="Review the Report">
    Examine the report summary and individual expenses. Identify the specific items that need attention. Take note of which expenses require corrections so you can provide detailed feedback.

    <Frame>
      <img src="/images/guides/web-app/approvals/review-report-details.png" alt="Reviewing report details and identifying items that need changes" />
    </Frame>
  </Step>

  <Step title="Click Request Changes">
    Click the **Request Changes** button in the top-right corner of the report detail view.

    <Frame>
      <img src="/images/guides/web-app/approvals/request-changes-button.png" alt="Request Changes button in the report detail view" />
    </Frame>
  </Step>

  <Step title="Add Comments Explaining What Needs to Change">
    A dialog appears where you can describe the required changes. Be specific about what needs to be corrected so the submitter can act quickly.

    **Examples of good change requests:**
    - "Please attach the receipt for the March 8 client dinner ($120)."
    - "The mileage rate used for the March 15 entry appears incorrect. Please recalculate using the current company rate."
    - "The team lunch on March 20 needs attendee names listed in the description."

    <Frame>
      <img src="/images/guides/web-app/approvals/change-request-comments.png" alt="Entering comments explaining required changes" />
    </Frame>
  </Step>

  <Step title="Flag Specific Expenses (Optional)">
    If supported by your organization's configuration, you can flag individual expenses within the report that need attention. This helps the submitter locate the exact items to fix.

    - Click the flag icon next to any expense that requires changes
    - Add a note specific to that expense
    - Flagged expenses are highlighted when the submitter opens the report

    <Frame>
      <img src="/images/guides/web-app/approvals/flag-expense.png" alt="Flagging a specific expense that needs correction" />
    </Frame>
  </Step>

  <Step title="Confirm the Request">
    Click **Submit Request** to send the report back to the submitter. The report status changes to **Changes Requested**.

    <Frame>
      <img src="/images/guides/web-app/approvals/confirm-request-changes.png" alt="Clicking Submit Request to send the report back" />
    </Frame>
  </Step>

  <Step title="Report Returns to the Submitter">
    The submitter receives a notification with your comments and any flagged expenses. The report appears in their list with a **Changes Requested** status and they can open it, make the necessary corrections, and resubmit.

    <Frame>
      <img src="/images/guides/web-app/approvals/returned-to-submitter.png" alt="Report returned to submitter with Changes Requested status" />
    </Frame>
  </Step>
</Steps>

## What Happens Next

After you request changes:

1. The report moves to **Changes Requested** status and leaves your approval queue
2. The submitter receives a notification with your comments
3. The submitter edits the report -- correcting expenses, attaching receipts, or updating descriptions
4. The submitter resubmits the report
5. The report returns to your approval queue with a **Pending** status
6. You review the updated report and approve, reject, or request further changes

<Note>
  **No limit on rounds.** You can request changes multiple times on the same report. Each round of comments is preserved in the report timeline so both parties can reference the full history.
</Note>

## When to Request Changes vs. Reject

| Use Request Changes when... | Use Reject when... |
|-----------------------------|--------------------|
| A few receipts are missing | The entire report is invalid |
| Categories need correction | Serious policy violations exist |
| Descriptions are incomplete | The report appears fraudulent |
| Minor amount discrepancies | The report was sent to the wrong approver |
| Attendee lists are missing | The report structure is fundamentally wrong |

## Tips for Effective Change Requests

- **Be specific** -- Reference exact expenses by date, merchant, or amount so the submitter can find them quickly
- **Explain why** -- State not just what needs to change but why, especially if it relates to a policy
- **Use flags** -- Flag individual expenses when possible instead of describing them in a general comment
- **Be constructive** -- Frame feedback as guidance rather than criticism to maintain a collaborative working relationship
