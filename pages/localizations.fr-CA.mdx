## Localisation de l'API

L'API est conçue pour prendre en charge plusieurs langues afin de répondre aux besoins des utilisateurs internationaux. Pour obtenir une version traduite d'une ressource, vous pouvez passer le paramètre `locale` dans votre requête ou utiliser l'en-tête `Accept-Language`. Par exemple, pour obtenir une ressource en français canadien, vous pouvez utiliser `locale=fr-CA` ou `Accept-Language: fr-CA`.

Cependant, il est important de noter que toutes les ressources ne sont pas nécessairement traduites dans toutes les langues. Si une traduction n'existe pas pour la langue demandée, la version par défaut de la ressource sera retournée.

### Exemple de requête

```http
GET /v1/resource?locale=fr-CA
Accept-Language: fr-CA
```

## Entités localisées

Les entités localisées disposent d'une API dédiée à la gestion de leurs traductions. Cette API est accessible à l'endpoint `/translations`. Vous pouvez utiliser cette API pour créer, mettre à jour, supprimer, obtenir ou lister les traductions des entités.

### Endpoints disponibles

- **Créer une traduction** : `POST /translations`
- **Mettre à jour une traduction** : `PUT /translations/{id}`
- **Supprimer une traduction** : `DELETE /translations/{id}`
- **Obtenir une traduction** : `GET /translations/{id}`
- **Lister les traductions** : `GET /translations`

### Exemple de création de traduction

```http
POST /v1/..../translations
Content-Type: application/json

{
  "locale": "fr-CA",
  "translatedField": "Valeur traduite"
}
```
