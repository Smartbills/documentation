# Limites de l'API avec Leaky Bucket

## Aperçu
Afin d'assurer une utilisation équitable et de préserver des performances optimales de l'API Smartbills, nous avons mis en place un système de limitation de taux reposant sur l'algorithme du **Leaky Bucket**. Cette approche permet de réguler le nombre de requêtes entrantes, garantissant ainsi un flux de trafic API stable et prévisible.

## Algorithme Leaky Bucket

L'algorithme du seau qui fuit constitue un mécanisme de gestion du trafic permettant d'assurer un flux constant de requêtes tout en évitant les pics de trafic susceptibles de surcharger le serveur. Il maintient un rythme constant de requêtes sortantes, où les requêtes excédentaires sont soit mises en attente, soit rejetées selon des limites établies.

### Fonctionnement

1. **Capacité du Seau** : Le seau possède une capacité fixe, représentant le nombre maximal de requêtes pouvant être temporairement stockées.
2. **Taux de Fuite** : Le seau se vide à un rythme constant, permettant le traitement d'un nombre déterminé de requêtes par seconde.
3. **Gestion des Requêtes** :
   - Lorsqu'une requête est reçue, elle est ajoutée au seau si de l'espace est disponible.
   - Si le seau est plein, la requête est soit rejetée, soit mise en attente, selon l'implémentation choisie.
   - Les requêtes sont traitées au rythme de fuite, assurant un flux régulier sans variations brusques.

## Politique de Limitation de Taux

### Limites

- **Requêtes Par Minute (RPM)** : Chaque utilisateur est autorisé à effectuer jusqu'à **100** requêtes par minute.
- **Capacité Maximale** : Le seau peut contenir jusqu'à **100** requêtes simultanément.
- **Extensions de Quotas** : Les quotas peuvent être étendus en fonction des cas d'utilisation spécifiques. Veuillez contacter le support pour plus d'informations.

### Exemple de réponse

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
Retry-After: 60

{
    "status": 429,
    "code":"RATE_LIMITED" ,
    "error": "Rate limit exceeded",
    "message": "You have exceeded your request limit. Please try again later."
}
```

### Codes de Réponse

Lorsque le nombre de requêtes dépasse la limite autorisée, l'API renverra un code d'état HTTP approprié :

- **429 Trop de Requêtes** : Ce code indique que l'utilisateur a dépassé la limite de taux permise. La réponse inclura un en-tête `Retry-After` précisant le délai en secondes avant qu'une nouvelle requête puisse être effectuée.
