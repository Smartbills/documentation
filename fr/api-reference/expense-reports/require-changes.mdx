---

## Aperçu

Demander des modifications à un rapport de dépenses soumis au lieu de l'approuver ou de le rejeter. Le statut du rapport passe à `changes_required`, et le soumetteur est notifié avec les modifications demandées. Le soumetteur peut ensuite mettre à jour le rapport et le resoumettre.

## Authentification

<ParamField header="Authorization" type="string" required>
  Jeton Bearer. Format : `Bearer YOUR_API_KEY`
</ParamField>

<ParamField header="x-tenant-id" type="string" required>
  Identifiant d'entreprise pour le contexte multi-locataire
</ParamField>

## Paramètres de chemin

<ParamField path="businessId" type="integer" required>
  L'identifiant unique de l'entreprise
</ParamField>

<ParamField path="reportId" type="integer" required>
  L'identifiant unique du rapport de dépenses
</ParamField>

## Corps de la requête

<ParamField body="changes" type="string" required>
  Description des modifications requises. Celle-ci sera visible par le soumetteur.

  Exemple : `"Please update expense #12347 with the correct amount and attach the itemized receipt."`
</ParamField>

## Réponse

Retourne le rapport de dépenses mis à jour avec le statut changé en `changes_required`.

<ResponseField name="id" type="integer">
  Identifiant unique du rapport de dépenses
</ResponseField>

<ResponseField name="title" type="string">
  Titre du rapport
</ResponseField>

<ResponseField name="status" type="string">
  Statut du rapport (sera `changes_required`)
</ResponseField>

<ResponseField name="totalAmount" type="number">
  Montant total du rapport
</ResponseField>

<ResponseField name="reportCurrency" type="string">
  Code de devise
</ResponseField>

<ResponseField name="changesRequestedBy" type="integer">
  Identifiant de l'utilisateur qui à demandé les modifications
</ResponseField>

<ResponseField name="changesRequestedAt" type="string">
  Horodatage de la demande de modifications (ISO 8601)
</ResponseField>

<ResponseField name="requestedChanges" type="string">
  Les modifications demandées
</ResponseField>

<ResponseField name="updatedAt" type="string">
  Horodatage de la dernière mise à jour (ISO 8601)
</ResponseField>

<RequestExample>

```bash cURL
curl --request POST \
  --url https://api.smartbills.io/v1/businesses/456/expense-reports/1001/request-changes \
  --header 'Authorization: Bearer YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --header 'x-tenant-id: 456' \
  --data '{
    "changes": "Please update expense #12347 with the correct amount and attach the itemized receipt."
  }'
```

```javascript JavaScript SDK
import { SBClient } from "@smartbills/sdk";

const client = new SBClient({ apiKey: "YOUR_API_KEY" });

const report = await client.expenseReports.requestChanges(1001, {
  changes: "Please update expense #12347 with the correct amount and attach the itemized receipt."
});

console.log("Status:", report.status);
console.log("Changes requested at:", report.changesRequestedAt);
```

```python Python SDK
from smartbills import Smartbills

client = Smartbills(api_key="YOUR_API_KEY")

report = client.expense_reports.request_changes(1001, {
    "changes": "Please update expense #12347 with the correct amount and attach the itemized receipt."
})

print(f"Status: {report.status}")
print(f"Changes requested at: {report.changes_requested_at}")
```

## Réponses d'erreur

| Code de statut | Code d'erreur | Description |
|------------|------------|-------------|
| 400 | VALIDATION_FAILED | Description des modifications manquante ou vide |
| 401 | UNAUTHORIZED | Clé API manquante ou invalide |
| 403 | FORBIDDEN | L'utilisateur n'est pas autorisé à demander des modifications sur ce rapport |
| 404 | NOT_FOUND | Rapport de dépenses non trouvé |
| 409 | INVALID_STATUS | Le rapport n'est pas au statut `submitted` |
| 429 | RATE_LIMIT_EXCEEDED | Trop de requêtes |
