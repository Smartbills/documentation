---
title: "Planifier un remboursement"
description: "Planifier une date de remboursement prévue pour un rapport de dépenses"
api: "POST https://api.smartbills.io/v1/businesses/{businessId}/expense-reports/{reportId}/payments/plan-reimbursement"
---

## Aperçu

Planifier une date de remboursement prévue pour un rapport de dépenses approuvé. Cela définit une date de paiement attendue et notifie l'employé du moment prévu pour le remboursement, sans traiter le paiement réel.

## Authentification

<ParamField header="Authorization" type="string" required>
  Jeton Bearer pour l'authentification. Format : `Bearer YOUR_API_KEY`
</ParamField>

## Paramètres de chemin

<ParamField path="businessId" type="integer" required>
  L'identifiant unique de l'entreprise
</ParamField>

<ParamField path="reportId" type="integer" required>
  L'identifiant unique du rapport de dépenses
</ParamField>

## Corps de la requête

<ParamField body="plannedDate" type="string" required>
  Date de remboursement prévue (format ISO 8601 : AAAA-MM-JJ). Doit être une date future.
</ParamField>

<ParamField body="notes" type="string">
  Notes sur le remboursement planifié (ex. : détails du cycle de paie)
</ParamField>

## Réponse

<ResponseField name="id" type="integer">
  Identifiant de l'enregistrement de remboursement planifié
</ResponseField>

<ResponseField name="reportId" type="integer">
  Identifiant du rapport de dépenses
</ResponseField>

<ResponseField name="plannedDate" type="string">
  Date de remboursement planifiée
</ResponseField>

<ResponseField name="notes" type="string">
  Notes de planification
</ResponseField>

<ResponseField name="status" type="string">
  Statut du rapport : `reimbursement_planned`
</ResponseField>

<ResponseField name="createdAt" type="string">
  Horodatage de la création du plan (ISO 8601)
</ResponseField>

## Règles de validation

- Le rapport doit être au statut `approved`
- La `plannedDate` doit être une date future
- Un seul remboursement planifié actif peut exister par rapport

## Réponses d'erreur

| Code de statut | Code d'erreur | Description |
|------------|------------|-------------|
| 400 | REPORT_NOT_APPROVED | Le rapport doit être approuvé avant de planifier un remboursement |
| 400 | INVALID_DATE | La date planifiée doit être dans le futur |
| 400 | PLAN_ALREADY_EXISTS | Un plan de remboursement existe déjà pour ce rapport |
| 401 | UNAUTHORIZED | Clé API manquante ou invalide |
| 403 | FORBIDDEN | Permissions insuffisantes |
| 404 | REPORT_NOT_FOUND | Le rapport n'existe pas |
