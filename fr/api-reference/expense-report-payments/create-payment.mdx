---
title: "Remboursement partiel"
description: "Rembourser partiellement des dépenses spécifiques d'un rapport de dépenses"
api: "POST https://api.smartbills.io/v1/businesses/{businessId}/expense-reports/{reportId}/payments/partial-reimburse"
---

## Aperçu

Rembourser individuellement des dépenses spécifiques d'un rapport de dépenses, plutôt que de rembourser l'intégralité du rapport en une seule fois. Ceci est utile lorsque différentes dépenses doivent être remboursées à des moments différents ou par des modes de paiement différents.

## Authentification

<ParamField header="Authorization" type="string" required>
  Jeton Bearer pour l'authentification. Format : `Bearer YOUR_API_KEY`
</ParamField>

## Paramètres de chemin

<ParamField path="businessId" type="integer" required>
  L'identifiant unique de l'entreprise
</ParamField>

<ParamField path="reportId" type="integer" required>
  L'identifiant unique du rapport de dépenses
</ParamField>

## Corps de la requête

<ParamField body="expenseReimbursements" type="array" required>
  Tableau d'entrées de remboursement individuelles par dépense

  <Expandable title="Objet Remboursement de dépense">
    <ParamField body="expenseReportExpenseId" type="integer" required>
      L'identifiant de l'élément du rapport de dépenses à rembourser (depuis la liste des éléments du rapport)
    </ParamField>

    <ParamField body="reimbursementAmount" type="number" required>
      Montant à rembourser pour cette dépense spécifique
    </ParamField>

    <ParamField body="notes" type="string">
      Notes spécifiques au remboursement de cette dépense
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="reimbursementNotes" type="string">
  Notes générales sur ce lot de remboursement partiel
</ParamField>

<ParamField body="reimbursementMethod" type="string">
  Mode de paiement utilisé. Options : `bank_transfer`, `check`, `cash`, `payroll`, `other`
</ParamField>

<ParamField body="reimbursementDate" type="string">
  Date à laquelle le remboursement à été effectué (format ISO 8601 : AAAA-MM-JJ). Par défaut, aujourd'hui.
</ParamField>

<ResponseField name="id" type="integer">
  Identifiant de l'enregistrement de remboursement partiel

<ResponseField name="reportId" type="integer">

<ResponseField name="expenseReimbursements" type="array">

  <Expandable title="Résultat de remboursement de dépense">
    <ResponseField name="expenseReportExpenseId" type="integer">
      Identifiant de l'élément du rapport

    <ResponseField name="notes" type="string">
      Notes de remboursement
    </ResponseField>
    <ResponseField name="status" type="string">
      Statut de remboursement de l'élément : `reimbursed`
    </ResponseField>
  </Expandable>

<ResponseField name="createdAt" type="string">
  Horodatage de l'enregistrement du remboursement (ISO 8601)

## Règles de validation

- Le rapport doit être au statut `approved` ou `partially_reimbursed`
- Chaque `expenseReportExpenseId` doit référencer un élément valide dans le rapport
- Le `reimbursementAmount` ne peut pas dépasser le montant approuvé pour chaque dépense
- Les dépenses déjà remboursées ne peuvent pas être remboursées à nouveau

## Réponses d'erreur

| Code de statut | Code d'erreur | Description |
|------------|------------|-------------|
| 400 | REPORT_NOT_APPROVED | Le rapport doit d'abord être approuvé |
| 400 | EXPENSE_ALREADY_REIMBURSED | Une ou plusieurs dépenses sont déjà remboursées |
| 400 | AMOUNT_EXCEEDS_APPROVED | Le montant de remboursement dépasse le montant approuvé |
| 401 | UNAUTHORIZED | Clé API manquante ou invalide |
| 404 | REPORT_NOT_FOUND | Le rapport n'existe pas |
| 404 | EXPENSE_NOT_FOUND | L'élément du rapport n'existe pas |
